WACRM Website CMS — how to view it
==================================

TL;DR
  Double-click  WACRM-CMS.html  (or open index.html — it forwards there).
  Nothing to install, no build step, no internet connection needed.
  The app is one self-contained file: HTML + CSS + JS + images inlined.

Three ways, pick one
--------------------

1. Just look at it (recommended)
     WACRM-CMS.html                      ← double-click this

2. Serve it locally (nicer URLs, no file:// quirks)
     python3 serve.py                    → http://localhost:4173

3. Develop it (hot reload, editable source)
     npm install
     npm run dev                         → http://localhost:5173

Where the four modules are
--------------------------
  Overview            sidebar → Overview              #/overview
  Sites & Domains     sidebar → Sites & Domains       #/sites
  Pages & Routes      sidebar → Pages                 #/pages
  Visual Builder      row pencil / "Edit Page" on any page   #/builder?page=…
                      (or sidebar → Visual Builder for the default page)

  Every screen has a "Prototype states" menu (beaker icon, top-right):
  Default / Empty / Error / Publish conflict / Permission denied (Viewer).

Which file is which
-------------------
  WACRM-CMS.html    the built, runnable app  ← the one you open
  index.html        Vite's dev entry. It needs the dev server; opened from
                    disk it shows a notice and forwards to WACRM-CMS.html.
  src/              React 19 + TypeScript source (what npm run dev serves)
  serve.py          zero-dependency static server (Python 3, no packages)
  BACKEND-PLAN.md   the backend contract (§7.19 the builder, §7.20 the interlink)
  AI-BUILDER-SPEC.md  AI mode: build a page / add a section / rewrite copy
  INTERLINK-PLAN.md   CMS ↔ CRM decisions (D1–D8) + the automation matrix
  MODULE-1..4-REVIEW.md  build-vs-spec review per module, with the defects found
  MODULE-5-REVIEW.md  block library vs the industry + the WACRM CRM integration plan
  MODULE-2-SPEC.md  the Sites & Domains UI/UX architecture specification
  STATE-COVERAGE.md every state for all four modules, how to trigger it, what is missing
  ROLLBACK.md       how to return to a previous checkpoint (tags + revert recipes)
  HANDOVER.md       generated state of the project — read this first if you are
                    picking the work up (human or AI agent): what is built, what
                    is verified, what is next, and the traps. Regenerate with
                    `npm run handover`; it updates itself on build and on qa.
  qa/               WebP captures of the audited states

If the page is ever blank
-------------------------
  - Make sure you opened WACRM-CMS.html (or index.html), not src/main.tsx.
  - Some browsers block file:// scripts for files that arrived inside a ZIP on
    macOS (quarantine). Either allow it, or use option 2: python3 serve.py
